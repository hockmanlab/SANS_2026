# Normalization

After filtering out low-quality cells, our Seurat object still contains raw UMI counts. Before we can cluster cells or compare gene expression between them, we need to **normalize** the data.

## Why normalize?

Raw UMI counts are affected by differences in **sequencing depth** between cells. A cell that was sequenced more deeply will generally show more detected UMIs, even if its true underlying gene expression is similar to a cell sequenced less deeply. If we compared raw counts directly, these technical differences in depth could be mistaken for real biological differences between cells.

**Normalization** corrects for this, so that expression values become more comparable across cells.

In this tutorial, we use **SCTransform**, Seurat's regularized negative binomial regression approach to normalization. SCTransform:

- accounts for differences in sequencing depth between cells;
- identifies **highly variable features** (genes that vary the most between cells and are therefore most useful for downstream analysis); and
- returns a transformed expression matrix that can be used for clustering, visualization, and other downstream steps.

> **Note:** SCTransform requires the `glmGamPoi` package (installed in [2.1 Installation](2.1_installation.md)) to run efficiently. Without it, SCTransform will still run but will be considerably slower.

## Running SCTransform

```r
# =============================================================================
# 12. NORMALIZATION USING SCTransform
# =============================================================================

query <- SCTransform(
  query,
  vars.to.regress = "percent.mt",
  verbose = FALSE
)

Assays(query)
query
```

**Output:**

```text
> Assays(query)
[1] "RNA" "SCT"

> query
An object of class Seurat
47871 features across 5000 samples within 2 assays
Active assay: SCT (22637 features, 3000 variable features)
 3 layers present: counts, data, scale.data
 1 other assay present: RNA
```

Running `SCTransform()` adds a new assay called **`SCT`** to the Seurat object and sets it as the **active assay**. The original raw counts remain untouched in the `RNA` assay, so you can always return to them if needed.

The `SCT` assay now contains three layers:

- **`counts`** — corrected counts
- **`data`** — log1p-transformed corrected counts
- **`scale.data`** — Pearson residuals for the 3,000 variable features, which will be used as input to PCA

Note that the total feature count (47,871) reflects both assays combined — but the two assays don't have the same gene set:

- **`RNA`** retains all **25,234 genes** — the same count established back when the Seurat object was first created (`min.cells = 3` in [2.2 Seurat Exploration](2.2_Seurat_exploration.md)). Nothing after that point removes genes from `RNA`; the downsampling and QC steps only filter *cells*.
- **`SCT`** reports **22,637 features**. SCTransform applies its own internal gene filter (`min_cells`, default 5), but it applies this to the 5,000-cell subset actually being modelled — not the original 8,601 cells. Some genes that passed the original `min.cells = 3` threshold no longer meet that bar once only 5,000 cells are considered, so SCTransform drops them.
- Of those 22,637 genes in `SCT`, the top **3,000** are flagged as **variable features** — the subset that will be used for PCA.

$$25{,}234 \text{ (RNA)} + 22{,}637 \text{ (SCT)} = 47{,}871 \text{ total}$$

> **Important — `vars.to.regress = "percent.mt"` is optional.**
>
> Regressing out mitochondrial percentage can reduce variation in the data associated with mitochondrial content. However, mitochondrial expression can also reflect genuine biological signal, such as cellular stress or cell state, rather than purely technical noise.
>
> Do **not** automatically regress `percent.mt` for every dataset. It is included here as an example. Whether to regress it should be a deliberate decision, justified by the characteristics of your own dataset.

## Inspecting the variable features

The set of variable features selected by SCTransform can be viewed with:

```r
head(VariableFeatures(query), 10)
```

These are the genes that will primarily drive the principal component analysis in the next step.

---

At this point, we have normalized the data using SCTransform, correcting for sequencing depth and mitochondrial content, and identified 3,000 highly variable features to use for downstream analysis.

The Seurat object is now ready for the next stage of the workflow: **principal component analysis (PCA)**.
