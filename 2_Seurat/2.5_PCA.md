# Principal Component Analysis (PCA)

With the data normalized, we can now reduce its dimensionality using **principal component analysis (PCA)**.

## Why reduce dimensionality?

Each **cell** can be thought of as a single point in space, and each **gene** as one axis (dimension) along which that point has a position — its expression value for that gene. A single-cell dataset can easily measure tens of thousands of genes, so each cell is a point living in a space with tens of thousands of dimensions, with thousands of cells scattered throughout it.

Working directly with that many dimensions is both computationally impractical and noisy — most genes (dimensions) contribute little useful information for distinguishing cell types or states; many are flat, redundant with other genes, or dominated by technical noise.

**PCA** reduces this high-dimensional expression data into a much smaller number of **principal components (PCs)**. Each PC is a weighted combination of genes and captures a component of the variation between cells, with the earliest PCs generally capturing the most variation.

Downstream steps such as clustering (`FindNeighbors`/`FindClusters`) and UMAP are performed using a small number of selected PCs rather than thousands of individual genes.

## How a PC score is actually computed

### Finding PC1 and PC2: the intuition

Before getting to the formula, it helps to picture what PCA is actually doing.

Imagine plotting every cell as a point in space (as in the previous section). If you step back and look at the overall shape of that cloud of points, it's rarely a perfect sphere — it's usually stretched more in some directions than others, because some genes vary a lot between cells while others don't.

PCA's first job is to find the **one straight line through that cloud where the cells are the most spread out** — the direction along which, if you projected every cell's position onto it, they'd still be as spread apart as possible. If you picked a line running the "short way" across the cloud instead, most cells would end up bunched close together on it, hiding the real differences between them. That best line — the one preserving the most spread — becomes the new axis called **PC1**.

Once PC1 has been found, PCA looks for the **next-best line that captures the most remaining spread**, but restricted to directions that are completely independent (uncorrelated) from PC1 — geometrically, at a right angle to it. That becomes **PC2**. This process keeps going, with each additional PC capturing the largest amount of spread left over after the earlier PCs, in a direction unrelated to all of them.

This is why the elbow plot (further down this page) drops steeply at first — PC1 and PC2 are doing most of the work of separating cells — and then flattens out, since later PCs are only picking up smaller and smaller amounts of leftover variation.


### From a direction to a formula: loadings and scores

Once PCA has found a direction like PC1, it needs to describe that direction using the only vocabulary available: the original genes. Two pieces make this work:

1. **Loadings** — every gene is given a weight (its "influence") for each PC, based on how much that gene contributes to the direction of greatest variation. Genes with little influence on a PC get weights near zero; genes that strongly separate cells along that PC get large weights (positive or negative, depending on which direction they push).
2. **Scores** — a cell's position on a given PC is calculated by multiplying its expression value for each gene by that gene's loading for that PC, and summing across all genes:

   ```text
   Cell's PC1 score = (gene1_expression × gene1_loading_on_PC1)
                     + (gene2_expression × gene2_loading_on_PC1)
                     + ... for every gene
   ```

This score is calculated for every cell, for every PC — and it's why the `DimHeatmap()` panels below make sense: the genes listed for each PC are simply the ones with the largest loadings (most influence) on that component.

> For a slower, worked-through version of this (including a visual of how the PC axes are found by rotating a line through the data), see the [HBC Training: Theory of normalization and PCA](https://hbctraining.github.io/scRNA-seq/lessons/05_normalization_and_PCA.html) lesson.

## Running PCA

```r
# =============================================================================
# PRINCIPAL COMPONENT ANALYSIS (PCA)
# =============================================================================

query <- RunPCA(
  query,
  assay = "SCT",
  verbose = FALSE
)
```

`RunPCA()` is run on the `SCT` assay, using the Pearson residuals of the 3,000 variable features identified by SCTransform.

## Examining genes contributing to each PC

`DimHeatmap()` lets us inspect which genes are driving variation along the first several PCs, using a subset of cells for speed.

```r
plot3 <- DimHeatmap(
  query,
  dims = 1:20,
  cells = 500,
  balanced = TRUE,
  nfeatures = 10,
  fast = FALSE
```

Each panel shows the genes with the strongest positive and negative loadings for a given PC, along with the cells that most strongly express them (yellow = higher expression, purple = lower). Early PCs (e.g. PC_1–PC_9) show clean, well-separated blocks of cells driven by genes such as `Rorb`, `Cxcl12`, `Ptprz1`, and `Slc4a4` — consistent with distinct biological populations.

By contrast, several later PCs (notably **PC_16, PC_18, and PC_19**) are dominated by mitochondrial genes (`mt-Co3`, `mt-Co2`) among their top loadings. This is a useful signal: it suggests that from around PC16 onward, the components are increasingly capturing mitochondrial/technical variation rather than clean biological structure, and are good candidates to exclude from downstream clustering.

## Elbow plot

The **elbow plot** shows how much variance is explained by each successive PC. It helps us decide how many PCs to carry forward into clustering and UMAP.

```r
elbow_plot <- ElbowPlot(
  query,
  ndims = 30
)

elbow_plot

ggsave(
  filename = file.path(
    PLOTS_DIR,
    "elbow_plot.png"
  ),
  plot = elbow_plot,

  height = 4,
  dpi = 300

```

The standard deviation explained drops sharply across the first five PCs (from roughly 20 down to 10), then continues to decrease more gradually through PC6–PC15, before flattening into a long, shallow tail out to PC30. There isn't a single sharp "elbow" — this is common with real data — so the plot alone gives a *range* (roughly PC10–PC15) rather than one obvious cutoff.

## Choosing the number of PCs

```r
# Number of PCs selected after inspecting the elbow plot and DimHeatmap.

N_PCS <- 1:15
```

Combining both diagnostics: the elbow plot shows the curve has largely flattened out by around PC15, and the heatmap confirms that PCs beyond that point (16, 18, 19) are increasingly driven by mitochondrial genes rather than distinct biological populations. **`N_PCS <- 15`** was therefore chosen as a reasonable cutoff that retains PCs with clear biological signal while excluding the mitochondrially-dominated later components.

> **Important:** The elbow plot is a heuristic, not a strict rule. Always cross-check your chosen cutoff against the `DimHeatmap()` output — a PC with a clean, interpretable gene signal is worth keeping even close to the "elbow," while a PC dominated by mitochondrial or ribosomal genes is a good candidate to drop even if it appears earlier in the ranking.

`N_PCS` is used throughout the rest of the workflow — for example in `FindNeighbors()`, UMAP, and later in label transfer (`FindTransferAnchors()`/`TransferData()`) — so it is worth taking the time to choose it thoughtfully rather than accepting a default value.

---

At this point, we have run PCA on the normalized data, inspected the gene loadings driving each component, and selected **15 principal components** to carry forward based on both the elbow plot and the heatmap.

The Seurat object is now ready for the next stage of the workflow: **clustering cells** based on the selected principal components.
