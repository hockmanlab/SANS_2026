Before reading the Cell Ranger output into Seurat, we first define the locations where the input data and analysis results will be stored.

```r id="jv2x9u"

# Output folder where results will be saved
OUT_DIR <- "/path/to/output_directory/"

  showWarnings = FALSE

  showWarnings = FALSE

# Project name
PROJECT_NAME <- "mouse_scRNA"
```

`DATA_DIR` should point to the **`filtered_feature_bc_matrix`** folder generated by Cell Ranger. `OUT_DIR` specifies where we will save the results of the Seurat analysis, while `PLOTS_DIR` creates a separate location for figures.

There are two common ways to load the Cell Ranger expression matrix into Seurat. We can either provide the folder containing the three matrix files or use the `.h5` file generated by Cell Ranger.

**Option A: Load the folder**

**Option B: Load the HDF5 file**

```r id="w8exw2"

```

For this tutorial, we will use the **10x h5 format**:

```r id="xv9c4u"

```

Both approaches provide the expression data in a format that can be used to create a Seurat object.

### Setting the future memory limit

We also set a limit for objects exported to parallel workers by the `future` package:

```r id="4k4zqv"
options(
  future.globals.maxSize = 10 * 1024^3
)
```

This is approximately **10 GB**. Importantly, this is **not a general R memory limit**. It controls the maximum size of objects that the `future` package is allowed to export when running tasks in parallel.


The 10x expression matrix is organised as:

* **Rows = genes/features**
* **Columns = cells/barcodes**
* **Values = UMI counts**

For example, a value in the matrix represents the number of UMIs observed for a particular gene in a particular cell.

At this stage, these are still the **raw UMI counts** produced by Cell Ranger. We have not yet performed the detailed quality-control steps that will be covered later.

## Creating the Seurat Object

We can now convert the 10x expression matrix into a **Seurat object**:

```r id="3o5k0s"
# =============================================================================
# 5. CREATE SEURAT OBJECT
# =============================================================================

query <- CreateSeuratObject(
  counts = query_10x,
  project = PROJECT_NAME,
  min.cells = 3,
  min.features = 200
)
```

The `CreateSeuratObject()` function stores the expression data together with information about the cells and genes, creating the main object that we will use throughout the Seurat workflow.

Two initial filtering parameters are specified here:

* **`min.cells = 3`** — only genes detected in at least 3 cells are retained.
* **`min.features = 200`** — only cells with at least 200 detected genes are retained.

These are **initial filtering parameters**, not the complete quality-control procedure. We will perform more detailed QC later using metrics such as the number of genes detected, total UMIs, and mitochondrial gene percentage.

We can inspect the newly created Seurat object using:

```r id="pl1l2r"
query

dim(query)

Assays(query)

head(colnames(query), 10)

head(rownames(query), 10)

query[1:10, 1:10]
```

These commands allow us to check the size of the object, identify the assays it contains, and inspect some of the cells and genes.

## Exploring Cell Metadata

Seurat also stores information about individual cells as **cell-level metadata**. This metadata can include QC measurements, sample information, experimental conditions, and other annotations.

We can inspect the metadata using:

```r id="9s6c4v"
# =============================================================================
# 6. VIEWING CELL METADATA
# =============================================================================

head(query[[]])

colnames(query[[]])

nrow(query[[]])

ncol(query[[]])

head(query$nFeature_RNA)

head(query$nCount_RNA)
```

Two important measurements are already available:

* **`nFeature_RNA`** — the number of genes detected in each cell.
* **`nCount_RNA`** — the total number of UMIs detected in each cell.

These values will be particularly useful during the **quality-control step**, where we examine the distribution of these measurements to identify low-quality or unusual cells.

## Optional Downsampling for Tutorial Runs

Single-cell datasets can contain thousands or even hundreds of thousands of cells, which can require substantial computational resources. For this tutorial, we provide an optional downsampling step that can be used when working with limited RAM.

```r id="2kq7nw"
# =============================================================================
# 7. OPTIONAL DOWNSAMPLING
# =============================================================================

# Only use this for RAM-constrained tutorial/testing runs.
# Randomly downsampling before QC is NOT recommended for final analysis.

DOWNSAMPLE_FOR_TESTING <- TRUE

DOWNSAMPLE_N <- 5000

if (DOWNSAMPLE_FOR_TESTING) {

  message(
    "Tutorial mode: randomly downsampling to ",
    DOWNSAMPLE_N,
    " cells before QC."
  )

  query <- subset(
    query,
    downsample = DOWNSAMPLE_N
  )
}

dim(query)
```

When enabled, this randomly selects **5,000 cells** for the tutorial analysis.

> **Important:** This downsampling step is intended only to make the tutorial easier to run on computers with limited memory. It is **not recommended for the final biological analysis**, because cells are being removed before quality control has been assessed. For a real analysis, the full dataset should be used whenever possible. For very large datasets, specialised approaches such as Seurat's **sketching workflow** can be considered.

At this point, we have successfully loaded the Cell Ranger data, created a Seurat object, inspected its basic structure and metadata, and, if necessary, reduced the dataset for tutorial purposes. We can now move on to **quality control (QC)**.
