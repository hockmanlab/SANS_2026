## Reading the 10x Data

Cell Ranger provides the filtered gene expression matrix in two commonly used formats:

1. A **folder** containing the matrix files (`matrix.mtx.gz`, `barcodes.tsv.gz`, and `features.tsv.gz`)
2. A **HDF5 (`.h5`) file**, such as `filtered_feature_bc_matrix.h5`

Both formats can be read into Seurat.

### Option A: Load the Filtered Matrix Folder

```r
DATA_DIR <- "/path/to/filtered_feature_bc_matrix/"

query_10x <- Read10X(
  data.dir = DATA_DIR
)
```

### Option B: Load the Filtered HDF5 File

```r
DATA_FILE <- "/path/to/filtered_feature_bc_matrix.h5"

query_10x <- Read10X_h5(
  DATA_FILE
)
```

### Method Used in This Tutorial

**For this analysis, we use the `filtered_feature_bc_matrix.h5` file.**

```r
DATA_FILE <- "filtered_feature_bc_matrix.h5"

query_10x <- Read10X_h5(
  DATA_FILE
)
```

The `Read10X_h5()` function reads the filtered 10x expression matrix directly from the HDF5 file and returns the expression matrix for downstream Seurat analysis.

> **Note:** Both approaches provide the 10x expression data in a format that can be used to create a Seurat object. The `.h5` approach is used here because the input data for this analysis are provided as `filtered_feature_bc_matrix.h5`.

## Setting the Future Memory Limit

We also set a limit for objects exported to parallel workers by the `future` package:

```r
options(
  future.globals.maxSize = 10 * 1024^3
)
```

This is approximately **10 GB**. Importantly, this is **not a general R memory limit**. It controls the maximum size of objects that the `future` package is allowed to export when running tasks in parallel.

# 5. Create the Seurat Object

We can now convert the 10x expression matrix into a **Seurat object**.

```r
# =============================================================================
# 5. CREATE SEURAT OBJECT
# =============================================================================

query <- CreateSeuratObject(
  counts = query_10x,
  project = PROJECT_NAME,
  min.cells = 3,
  min.features = 200
)
```

The `CreateSeuratObject()` function stores the expression data together with cell-level information, creating the main object used throughout the Seurat workflow.

Two initial filtering parameters are specified:

- **`min.cells = 3`** — genes must be detected in at least 3 cells to be retained.
- **`min.features = 200`** — cells must contain at least 200 detected features to be retained.

These are **initial filtering parameters**, not the complete quality-control procedure. More detailed QC will be performed later using metrics such as the number of detected genes, total UMIs, and mitochondrial gene percentage.

# 7. Optional Downsampling for Tutorial Runs

Single-cell datasets can contain thousands or hundreds of thousands of cells and may require substantial computational resources. For this tutorial, an optional downsampling step is provided for computers with limited RAM.

```r
# =============================================================================
# 7. OPTIONAL DOWNSAMPLING
# =============================================================================

# Only use this for RAM-constrained tutorial/testing runs.
# Randomly downsampling before QC is NOT recommended for final analysis.

DOWNSAMPLE_FOR_TESTING <- TRUE

DOWNSAMPLE_N <- 5000

if (DOWNSAMPLE_FOR_TESTING) {

  message(
    "Tutorial mode: randomly downsampling to ",
    DOWNSAMPLE_N,
    " cells before QC."
  )

  query <- subset(
    query,
    downsample = DOWNSAMPLE_N
  )
}

dim(query)
```

**Output:**

```text
Tutorial mode: randomly downsampling to 5000 cells before QC.

[1] 25234 5000
```

When enabled, this randomly selects **5,000 cells** for the tutorial analysis.

> **Important:** Downsampling is used here only for a RAM-constrained tutorial/testing run. It is **not recommended for the final biological analysis**, because cells are removed before their quality has been assessed. For the final analysis, the full dataset should be retained whenever possible.
