# Principal Component Analysis (PCA)

With the data normalized, we can now reduce its dimensionality using **principal component analysis (PCA)**.

## Why reduce dimensionality?

A single-cell dataset can easily contain expression measurements for tens of thousands of genes across thousands of cells. Working directly with that many dimensions is both computationally impractical and noisy — most genes contribute little useful information for distinguishing cell types or states.

**PCA** reduces this high-dimensional expression data into a much smaller number of **principal components (PCs)**. Each PC is a weighted combination of genes and captures a component of the variation between cells, with the earliest PCs generally capturing the most variation.

Downstream steps such as clustering (`FindNeighbors`/`FindClusters`) and UMAP are performed using a small number of selected PCs rather than thousands of individual genes.

## Running PCA

```r
# =============================================================================
# 13. PRINCIPAL COMPONENT ANALYSIS (PCA)
# =============================================================================

query <- RunPCA(
  query,
  assay = "SCT",
  verbose = FALSE
)
```

`RunPCA()` is run on the `SCT` assay, using the Pearson residuals of the 3,000 variable features identified by SCTransform.

## Examining genes contributing to each PC

`DimHeatmap()` lets us inspect which genes are driving variation along the first several PCs, using a subset of cells for speed.

```r
DimHeatmap(
  query,
  dims = 1:20,
  cells = 500,
  balanced = TRUE
)
```

### PCA Heatmap

![PCA heatmap](../images/pca_heatmap.png)

Each panel shows the genes with the strongest positive and negative loadings for a given PC, along with the cells that most strongly express them (yellow = higher expression, purple = lower). Early PCs (e.g. PC_1–PC_9) show clean, well-separated blocks of cells driven by genes such as `Rorb`, `Cxcl12`, `Ptprz1`, and `Slc4a4` — consistent with distinct biological populations.

By contrast, several later PCs (notably **PC_16, PC_18, and PC_19**) are dominated by mitochondrial genes (`mt-Co3`, `mt-Co2`) among their top loadings. This is a useful signal: it suggests that from around PC16 onward, the components are increasingly capturing mitochondrial/technical variation rather than clean biological structure, and are good candidates to exclude from downstream clustering.

## Elbow plot

The **elbow plot** shows how much variance is explained by each successive PC. It helps us decide how many PCs to carry forward into clustering and UMAP.

```r
elbow_plot <- ElbowPlot(
  query,
  ndims = 30
)

elbow_plot

ggsave(
  filename = file.path(
    PLOTS_DIR,
    "elbow_plot.png"
  ),
  plot = elbow_plot,
  width = 8,
  height = 4,
  dpi = 300
)
```

### Elbow Plot

![Elbow plot](../images/elbow_plot.png)

The standard deviation explained drops sharply across the first five PCs (from roughly 20 down to 10), then continues to decrease more gradually through PC6–PC15, before flattening into a long, shallow tail out to PC30. There isn't a single sharp "elbow" — this is common with real data — so the plot alone gives a *range* (roughly PC10–PC15) rather than one obvious cutoff.

## Choosing the number of PCs

```r
# Number of PCs selected after inspecting the elbow plot and DimHeatmap.

N_PCS <- 15
```

Combining both diagnostics: the elbow plot shows the curve has largely flattened out by around PC15, and the heatmap confirms that PCs beyond that point (16, 18, 19) are increasingly driven by mitochondrial genes rather than distinct biological populations. **`N_PCS <- 15`** was therefore chosen as a reasonable cutoff that retains PCs with clear biological signal while excluding the mitochondrially-dominated later components.

> **Important:** The elbow plot is a heuristic, not a strict rule. Always cross-check your chosen cutoff against the `DimHeatmap()` output — a PC with a clean, interpretable gene signal is worth keeping even close to the "elbow," while a PC dominated by mitochondrial or ribosomal genes is a good candidate to drop even if it appears earlier in the ranking.

`N_PCS` is used throughout the rest of the workflow — for example in `FindNeighbors()`, UMAP, and later in label transfer (`FindTransferAnchors()`/`TransferData()`) — so it is worth taking the time to choose it thoughtfully rather than accepting a default value.

---

At this point, we have run PCA on the normalized data, inspected the gene loadings driving each component, and selected **15 principal components** to carry forward based on both the elbow plot and the heatmap.

The Seurat object is now ready for the next stage of the workflow: **clustering cells** based on the selected principal components.
